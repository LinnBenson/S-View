# 健康数据读取

`system.getHealthInfo` 经 SystemApiRequest 分发到 HealthInfoReader，在接口线程等待 IO 协程。运行窗口只允许一个在途请求，后台化或关闭取消 Job。整体查询限时 15 秒，取消后不把未完成查询伪装为零值。HealthSnapshot 统一字段、单位、时间与状态。

手机使用 Health Connect 1.1.0，只申请六类读取权限，不申请写入、后台读取或历史扩展权限。今日步数、距离和总热量使用系统聚合接口；心率按一天一个窗口向前查询，页内比较采样时间，最多回看 30 天。血氧取最新点记录，睡眠分页寻找最近结束的会话并返回会话起止时长。缺失权限与单项读取失败不会抹掉其他已获取字段。权限说明页向用户说明脚本可以继续处理或发送读取结果。

手表在 API 30 以上才加载 Health Services 1.1.0。Manifest 仅对该库覆盖 minSdk 声明，保留手机 API 26 支持；所有入口均做系统版本检查。通过能力查询选择支持的日累计步数、距离、热量与心率；短时注册 PassiveListenerCallback，刷新已有被动批次，最多等待 5 秒后注销，不使用 MeasureClient、ExerciseClient 或后台 PassiveListenerService。日累计取最新值，不累加批次；接收点使用开机时钟转换为 Unix 时间并排除昨日数据。血氧和睡眠历史不通过这个公共接口提供，标记为 unsupported。

Health Services 同一应用只能注册一个被动回调，因此多个窗口的请求使用进程级 Mutex 串行执行。注销 Future 必须在下一次注册前完成，避免取消后的迟到注销删除新监听。请求结束会停止接收迟到的数据，短时等待注销最多 2 秒；注销操作自身不因窗口取消而取消。

健康数据不加入手表同步包，不保存健康缓存。各端读取自己的数据源，结构一致不代表记录值一致。授权仅由用户点击权限入口发起，脚本调用不会自动申请权限。
