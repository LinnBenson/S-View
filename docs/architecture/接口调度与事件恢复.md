# 接口调度与事件恢复

系统接口分为快速查询、慢操作和关闭/取消三个有界执行通道。定位、无线扫描、健康读取、热点申请、安装准备及图片解码不会占用快速查询线程；关闭窗口和关闭服务不排在这些慢操作后面。各线程池允许空闲回收，不增加常驻轮询。

窗口事件使用稳定的网页 EventTarget，底层 EventSource 断线后按退避策略重建。重建携带最近已处理的序号，原生重放其后的历史，网页按序号去重，NFC 和局域网服务不必重新注册回调。连续恢复失败会返回 CONNECTION_LOST；网络恢复、页面恢复或下次调用可以重新尝试。

原生只调度一个事件排空任务，不再为每条事件占一个线程池排队项。历史最多保留 512 条且不超过 2 MiB 文本预算；离线时间过长导致游标过期时推送 EVENT_GAP，不能假装完整收到全部事件。关闭与 ready 状态在重连时补发。长时间离线的数据恢复需要调用方重新读取服务状态。

系统、交互和文件桥的 Error 保留中文 message 并提供 code。通用码包括 INVALID_ARGUMENT、PERMISSION_DENIED、TIMEOUT、CANCELLED、NOT_FOUND、ALREADY_EXISTS、INVALID_STATE、IO_ERROR、INTERNAL_ERROR；桥接限流使用 BUSY。已有原生网络和 NFC 专用错误码继续保留。

健康快照在同一运行窗口内合并并发读取，成功结果短暂缓存五秒；缓存保留原始查询时间和采样时间。后台、窗口关闭、权限、时区或日期变化使缓存失效。文件与网络桥按设备选择有界分块（手机 64 KiB、手表 256 KiB），仍逐块确认，不提前堆积整个文件；原生文件复制继续使用 64 KiB 缓冲。

chatServer/uploadServer 的单文件和单图片限制默认均为 512 MiB，可通过 maxFileSizeMB/maxImageSizeMB 设为 1–512。聊天附件缓存总额为 512 MiB；关闭服务清理会话缓存。uploadServer 完成后保存到 Download，不受聊天缓存总额限制。返回句柄增加只读 token，访问地址不拼接访问码。

外部启动同时观察项目匹配与同步状态，等待同步结束后启动首个匹配项目。运行中不因列表更新重复打开窗口；手表兜底选择卡片使用紧凑的单列布局。

## 启动准备

运行窗口在首帧反馈后即可创建冷引擎，不再等待入场动画结束。首页初始化只加载配置和补齐模板，运行文件由统一的 `prepareRun` 路径按目标项目签名检查，保存、同步和清缓存的互斥保持不变。

手表启动先固定旧工作区目录清单，再延后回收；随后新建的同步目录不在清单中，删除前再次检查当前指针。磁贴入口只校验令牌及已发布项目 ID，完整配置由工作区加载。手机快捷启动与手表磁贴准备期间跳过不必要的首页列表绘制。
