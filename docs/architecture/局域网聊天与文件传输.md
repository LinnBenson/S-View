# 局域网聊天与文件传输

`sview.network.chatServer(options)` 和 `sview.network.uploadServer(options)` 返回 Promise。服务启动后返回 `name`、`url`、`port` 和幂等的 `close()`；聊天服务另有 `send(text)`，广播系统消息并返回消息对象，不回调自身的 `onMessage`。

配置包括 `name`、`server`、`port`、`token`、`maxFileSizeMB`、`maxImageSizeMB`。监听地址默认为当前 Wi-Fi IPv4；`10.*` 匹配第一个活跃的 `10.` 网卡，完整 IPv4 必须属于本机。显式 `0.0.0.0` 监听所有网卡，返回当前 Wi-Fi 的访问地址。默认端口 8080，访问码为空。文件和图片默认上限均为 512 MB，可配置为 1–512 MB。

## 接口与事件

聊天消息含 `id`、`senderId`、`type`、`time`、`text`、`name`、`size`、`system`。类型为 text/image/file，时间为毫秒时间戳，不适用的字段为 null。访客身份由服务器创建，并使用本会话的 HttpOnly、SameSite Cookie 保持。聊天附件不自动存入 Download，只供会话内查看与下载；关闭后清理。消息上限 10000 条，附件总量上限 512 MB，满额时拒绝新增而不删除历史。

上传服务的 `onText(text)` 接收文字。`onFile(id, percent, path)` 接收文件进度，`onImage(id, percent, path)` 单独接收图片进度。id 是每次上传生成的唯一字符串，同一次上传的所有进度与完成回调保持不变，同一文件重新上传会生成新 ID。接收期间 path 为 false；保存完成后才报告 100 和实际 `device:/Download/文件名`。聊天和上传服务遇到网络读取失败（包括超时）或正文提前结束时，触发 `onCancel(id)`，不触发 onError，也不关闭服务；磁盘写入或图片校验等失败仍触发 `onError({ message })`，不报告保存成功。图片使用边界解码验证格式，不在应用中解码整张图片。

启动失败通过 onError 报告并拒绝 Promise；运行故障、磁盘写入或文件校验失败通过 onError 报告。主动关闭或运行中停止触发一次 onClose()，启动失败不触发 onClose。关闭请求响应与 SSE 事件共用同一状态，避免重复通知。网络丢失或监听地址改变时服务停止；显式监听所有网卡时不跟随单张网卡停止。不同服务需要不同端口，一个运行窗口最多同时持有四个服务。

## 文件与生命周期

接收流以 32 KiB 缓冲写入文件，不通过 JavaScript 传递文件内容。聊天附件写入应用缓存；上传服务直接写入 Download 中的隐藏临时文件，同步磁盘并校验图片后改名发布，避免完整复制和重复同步。同名文件在应用级锁下选择递增序号。关闭时中断连接，删除未完成文件；Download 中已完成文件保持不变。

RuntimeApiBridge 持有服务管理器，项目关闭和应用退出统一释放。每个实例独立管理会话，旧句柄不会关闭后来的新服务。进程异常退出的临时文件在下次启动服务或清除缓存时清理。清除缓存沿用工作区规则，要求先关闭所有运行窗口。

## 传输边界

局域网监听与 ProjectServer 分离，不能访问项目资源、系统接口或工作区编辑器。访问码检查覆盖上传入口；聊天记录与附件要求有效会话。Host 只接受监听设备的直接 IP 和端口，浏览器跨来源请求被拒绝。请求头限制 16 KiB，不接受重复头或分块上传，文件严格按 Content-Length 接收。每个服务最多八个并发请求，同时接收一个上传；读取空闲超时 15 秒，接收总时长上限 30 分钟。

聊天页面通过最长 10 秒的等待请求接收新增消息，空闲时减少网络唤醒。脚本事件共用运行窗口的 SSE 通道，回调仍由网页执行，不序列化函数。关闭项目不依赖回调执行成功。

## 页面来源

聊天页面与上传页面沿用 And JS 的 `http-chat.html`、`http-server.html`，按项目所有者要求复用。页面名称改为 S View，鉴权头、接口交互和保存提示对齐本项目；原生实现独立编写，复用 S View 的设备存储与运行窗口生命周期。

上传网页仅允许当前请求的结束事件清理上传状态，防止旧请求影响后续上传。

自定义 server 转交脚本的请求遇到网络传输中断或请求超时时，触发 onCancel(requestId)，不触发 onError；仍发送 request-end 取消脚本请求并清理请求和响应临时文件。脚本处理异常、正文超限及磁盘失败保留 onError。聊天和上传服务只在文件未提交时报告 onCancel，保存后的响应连接断开不会将已完成文件改报取消。
