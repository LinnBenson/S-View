# 手表工作区与同步

同一安装包通过系统 watch 特征选择手机或手表界面。手表首页只读取项目配置；运行文件按需生成，浏览器在运行项目时加载。权限页复用权限申请逻辑，使用适合圆屏的紧凑布局。

手机的 WatchConnection 只在连接页订阅 Wear OS capability，并保存项目选择与排序。同步通过 ChannelClient 传输带长度与 SHA-256 的 ZIP 文件流，接收端回复最终应用结果。连接页不使用轮询，离开应用时关闭活动通道。

WatchSyncArchive 保存选中项目配置和资源、全部全局模板与共享数据库快照。项目根目录 cache 不参与传输。接收时检查路径、大小、条目数量、项目编号、系统模板与数据类型，数据库在新工作区中单独构建。

手表先把数据放入独立的工作区代次，校验完毕后停止当前运行、关闭旧数据库连接，再通过 AtomicFile 切换工作区指针。项目、模板和数据库因此同时切换；未完成的接收不会覆盖旧工作区。旧代次在切换完成后回收，进程中断残留在下次初始化时回收。同步保留手表的浏览器数据，包括 Cookie、localStorage 和 IndexedDB；手表手动点击清除缓存时仍会清除网页数据、缓存与日志。

运行窗口不显示关闭按钮。WatchEdgeSwipe 只识别从圆屏左侧边缘开始的水平右滑，普通网页区域的操作继续交给运行引擎；项目内容不额外增加圆屏留白。

手表系统页使用 Wear Compose 的 ScalingLazyColumn、Chip 和 PositionIndicator，沿用官方的圆屏边缘缩放、旋转输入和滚动指示。项目宫格把一行作为一个缩放单元；权限项分别作为独立列表项，避免整个权限页被当作单个大项缩放。列表与宫格选择单独保存在手表本地偏好中，不随手机同步覆盖。

## 系统磁贴

手机 `WatchConnection.tileProjects` 保存独立的磁贴选择，默认空集、最多八个，并随项目移除同步清理。快照中的 `tileProjects` 只记录已选择项目的 ID，接收时检查数量、重复项及归属，写入同一工作区代次的 `tile-projects.json`，随原子切换一起发布。

`WatchProjectTileService` 由 Wear OS 磁贴系统绑定使用。单线程后台任务读取当前代次的配置，构造原生 ProtoLayout 弧形扇区；布局沿用项目顺序、图标和配色。读取配置期间持有工作区切换锁，避免读到已回收的代次。同步完成请求系统刷新，不设置周期任务。名称使用原生 ArcText 沿外圈排布，按可用弧长截短；项目图标位于文字内侧，中央只显示可点击的品牌标记。图标按需转换成带明确宽高和格式的 ARGB_8888 像素数据，资源版本包含图标集合，资源请求不会误用同步后的另一组图标。

系统磁贴必须通过公开 Activity 执行 LaunchAction。`WatchTileLaunchActivity` 检查本地随机令牌及当前磁贴项目集合，再签发进程内一次性 WidgetRunRequest，交给 WatchActivity 的现有运行准备流程；公开入口不接受任意项目启动。首页列表与磁贴复用同一运行方法，运行前等待工作区就绪及同步结束。
